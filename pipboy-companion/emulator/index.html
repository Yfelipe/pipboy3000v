“Run in RAM” resets the interpreter first, then types the program into the REPL.
          “Save as boot code” stores it in Storage as .bootcde, which runs at every boot (on a loaded
          dump that replaces the device's firmware until you load the dump again). “Save to Storage & load()” keeps the
          boot code and runs the file instead, from flash, as load("app.js") does on the device.

      


      

        

        

        Starter Pip-Boy or a dump
        
The starter Pip-Boy needs no device: the companion's apps and holotapes with sample notes, lists, messages and radio presets. Or a dump made on the dashboard's Backup & restore page: its Storage goes into flash, its SD card files onto the emulated card.

        

          
          
        

        

        


        

        Add Pip-OS (the stock interface)
        
The stock interface isn't included: Pip-OS belongs to The Wand Company. They publish each update as a zip (the one their Pip-Boy upgrade page installs): download it with the button below, then add it here as it is. Its files go on the emulated SD card and FW.JS becomes the boot code, as on the device. Storage starts again with Pip-OS and the starter's apps (with Extra Storage they all fit). A dump of your own Pip-Boy already has Pip-OS.

        SD card files
        
Copy a folder onto the emulated card, e.g. a copy of the real card to add videos the dump skipped. Files with the same path are replaced.

        

          
          
        

        


        


        

        Storage files
        
Write files into flash, as require("Storage").write(name, data).
